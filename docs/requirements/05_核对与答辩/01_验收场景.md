# MVP需求验收场景

版本V1.2，2026-10-23。以下为待执行场景，不是已通过的测试。首版采用单人顺序操作，验证正常业务与基本输入、权限、状态规则；复杂异常测试延期。

预置主人A、主人B、工作人员、管理员账号；四类房型各有演示房间；A有猫和犬档案。除具体计费示例外，日期以演示当日及未来日期构造。11月1日至4日等固定示例可在可控测试日期执行，不能为演示而跳过生产日期校验。

## 本版验收

| 编号 | 需求 | 操作 | 预期结果 |
|---|---|---|---|
| TC01 | FR01 | 用预设账号登录并退出 | 进入对应角色页面，退出后受保护页面要求登录 |
| TC02 | FR01/FR09 | A访问B的宠物、预约或照护数据 | 服务端拒绝；A仅看到本人信息 |
| TC03 | FR02 | 创建宠物，填写物种、正体重及联系人；再尝试缺必填项 | 合法档案保存并刷新可见；缺项简单提示 |
| TC04 | FR03 | 以猫和犬分别查询有效日期 | 展示匹配房型、日价、计划总价及连续可用数量；不占房 |
| TC05 | FR04 | 主人确认有效房型、日期和当前价格后提交 | 生成待审核单，保存日价快照和房型，不分房 |
| TC07 | FR05 | 顺序审核重叠预约并选择房间 | 普通可用性检查不允许重复安排；其他空房仍可选；不测并发 |
| TC09 | FR04/FR12 | 80元提交后管理员将房型改为90元，再审核原单 | 原单仍为80元，新提交单按90元 |
| TC10 | FR06 | 取消本人待审核或已确认订单 | 已取消，无取消费，释放计划占用 |
| TC11 | FR06 | 到计划离店日仍未入住，工作人员手动标记失约 | 已失约并释放计划占用，无需等待定时任务 |
| TC12 | FR07 | 在开始日、资料通过且实际空房时入住 | 产生一条入住记录，预约已入住 |
| TC15 | FR08/FR09 | 工作人员创建并完成文字照护任务，主人查看 | 显示类型、计划时间、执行人员、完成时间及说明 |
| TC17 | FR11 | 80元/天，预约11月1日至4日，3日接回 | 基础费240元，无逾期费，不减费 |
| TC18 | FR11 | 同上预约5日离店 | 基础费240元、逾期费80元、合计320元，无附加收费 |
| TC23 | FR03 | A房只空前半段、B房只空后半段，查询整个区间 | 两房均不计入连续可用数量，不拼接余量 |
| TC24 | FR04 | 页面显示80元，提交前管理员调为90元 | 展示90元及新总价，主人重新确认后才按90元创建订单 |
| TC25 | FR05 | 工作人员填写原因并驳回待审核单 | 已驳回、不占房；主人可在详情查看原因 |
| TC26 | FR07/FR11 | 预约1日至4日，2日到店并填写迟到原因 | 可入住，离店日不变，基础费仍按3天 |
| TC27 | FR07 | 早于计划开始日或到达计划离店日后申请该单入住 | 简单提示不符合日期条件，不创建入住 |
| TC28 | FR08/FR11 | 在住有待完成与已完成任务，收款结单后查看 | 未完成转已取消，完成记录保留；不能再新增或完成任务 |
| TC29 | FR09 | 主人打开本人订单后刷新页面 | 状态、房型、价格、照护和账单仍可读取；空记录有空状态 |
| TC30 | FR11 | 主人核对，工作人员选择现金或线下转账全额收款 | 保存账单及收款、操作人和时间，预约已完成，入住结束，释放实际占用；未确认收款不结单 |
| TC31 | FR12 | 管理员修改房型价格及无未完成预约房间的名称/体重限制 | 新数据保存可读取，历史订单价格快照不变 |

同日不同时间退房不增加逾期费；跨自然日才按BR09计算。页面在手机浏览器可读，管理端在电脑浏览器可完成上述操作。

## 本轮不验收

TC06幂等提交、TC08并发审核、TC13逾期占房协调、TC14取消入住竞争、TC16自动提醒、TC19故障与重试、TC20维护排班、TC21人员停用、TC22通知补发，以及备份恢复、压测、图片和附加收费。

延期项不等于系统已具备对应保障，也不要求为本轮演示构造专门异常恢复流程。
