# 课程与提交说明

适用项目：宠物寄宿 Web 系统；整理日期：2026-11-14。

## 1. 使用方式

业务内容统一见[需求说明书](../01_项目需求/需求说明书.md)。本轮采用主人、店员、店长、系统管理员四类角色。旧 UML 图及对应报告草稿已删除，待按本轮需求重新建模和编写报告。

本文件合并课程对照、AI辅助与人工核验模板、提交清单和答辩提示。旧版业务政策及检查记录由 Git 保存，不另设历史版本文件夹。

## 2. 课程依据与任务

依据为用户提供的《软件需求工程》实验指导书 PDF、DOCX 和实验报告评分细则 PDF。课程要求与项目自行选择的业务规则分别说明，不将课堂案例政策直接套用到本项目。

| 实验 | 课程任务 | 应准备的成果 |
|---|---|---|
| 实验一：软件功能描述 | 分析重庆师范大学教务系统功能，对比 AI 结果与人工观察，填写体验表并结合个人体会 | 单独完成教务系统体验分析，不以宠物寄宿项目替代 |
| 实验二：用例图 | 提取参与者、用例、包含/扩展/泛化关系与布局，使用 Visio 绘图并进行 AI 检查 | 四类参与者、用例清单、关系依据、用例图和充分文字说明 |
| 实验三：类图 | 识别类、属性、方法和关系，对比人工设计与 AI 结果 | 领域类图、元素说明、多重性和实际人工对比记录 |
| 实验四：顺序图 | 分析场景对象及消息顺序，需求变化后调整交互 | 关键场景顺序图、交互说明和实际变更前后对照 |
| 实验五：活动图 | 分析活动、判断、合并和并行，并绘图说明 | 业务活动图、各路径说明和人工走查记录 |

实验二至五采用本小组选题并配以充分文字说明。课堂案例是否需随报告附交，按教师通知确认。

指导书未为实验二提供固定报告模板，其中九张功能描述表属于实验一。报告可按实验目标、任务依据、工具环境、真实操作步骤、图与说明、AI输出及人工修订、结果与反思组织；教师另有模板时按其要求调整。

实验二明确要求使用 Visio。后续若采用 draw.io、PlantUML 或 SVG，不能称其为 Visio 原生工程；替代工具是否获准需按教师要求确认。

## 3. 建模核验要点

- 用例图：参与者是与系统交互的角色，宠物是业务对象；包含、扩展和泛化需要业务语义依据。
- 类图：解释职责、属性、方法、关系及多重性；领域类图不直接等同数据库表。
- 顺序图：明确场景、前置条件、消息、分支和结果；变更后检查受影响的交互。
- 活动图：主流程、判断条件、异常路径及结束条件完整，并行符合业务。
- 跨图一致性：角色、术语、订单状态和责任划分与需求说明书一致。
- 追踪：需求、用例、模型和验收相互对应；不混用 V1.2 编号与新草案编号。

## 5. 提交检查

- [ ] 已核对截止时间、报告模板、命名规范和提交格式。
- [ ] 姓名、学号、班级、组号与实际分工完整。
- [ ] 已确认业务与待明确事项区分清楚。
- [ ] 图与报告已根据四角色需求重新完成，未混用旧版业务政策。
- [ ] 关系方向、多重性、消息顺序和判断条件经过人工核验。
- [ ] 图源能用对应工具打开，文字清晰，图题及图片链接正确。
- [ ] 报告具有建模依据、关键元素、流程及相关分支说明。
- [ ] 真实截图、AI输出、人工修订和需求变更记录已按要求补齐。
- [ ] 实验一及需附交的课堂练习已经单独检查。
- [ ] 未把计划、验收目标、静态检查或历史结果写成当前实测通过。
- [ ] 最终版式、分页、术语与编号已检查。

评分细则关注题目符合度、图的正确性、文字说明和格式；高分档涉及亮点或创新，未规定固定权重、图数或开发技术栈，不据此承诺分数。

## 6. 待补充信息与答辩准备

待教师或小组补充：统一模板、截止时间、命名和分组要求、课堂练习附交范围、替代工具许可、实验一真实使用资料、最终图源格式。

答辩应能解释项目目标、四类角色权限、确认与入住的区别、照护责任及执行记录、异常处理流程、模型与需求的对应关系。收费及取消等未确定政策应如实说明，不沿用旧版答案。

检查时记录日期、文件或 Git 版本、工具、范围与结果。XML或链接等静态检查不能证明业务运行、PlantUML编译或Visio绘制已完成。
