# 宠物寄养系统 MVP 需求基线

版本：V1.2；日期：2026-10-23；状态：按用户本轮确认收敛。

## 本版目标

实现单门店、浏览器访问、数据可保存的最小业务闭环：预设账号登录 → 宠物建档 → 查询房型 → 提交预约 → 审核分房 → 入住 → 手动照护 → 离店收款。

本版固定四类房型：猫舍标间、猫舍豪华间、犬舍标间、犬舍豪华间。一张预约一只宠物，一宠一间。

## 确认规则

1. 使用预设主人、工作人员、管理员账号；不做自主注册、短信验证和找回密码。
2. 每个房型统一日价并关联多个实际房间。余量为整个预约区间内可连续使用的具体房间数，不是每日余量的最小值；待审核不占房。
3. 提交预约时读取当前日价并保存快照。若页面展示价格已变化，先展示新价格，由主人再次确认后提交；审核不得改价。此项属于已确认的正常价格确认步骤。
4. 预约区间为 [开始日, 离店日)，最少一天。允许区间内延迟入住，工作人员记录原因；早于开始日或到达计划离店日后不能办理该单入住。
5. 采用日期级规则，记录实际操作时间，不做12点/14点限制、小时收费及清洁排班。同一自然日内晚几个小时离店不另收费用。
6. 提前离店和延迟入住不减免原计划基础费；跨过计划离店日按自然日差收取逾期费。
7. 工作人员手动创建照护任务、填写文字完成记录。离店时仍未完成的任务转已取消，保留历史；离店后不再新增或完成任务。
8. 主人核对账单，工作人员登记线下全额收款并结单；账单仅含基础费和逾期费。
9. 正常流程保留未入住取消、工作人员驳回；失约由工作人员手动标记，首版不做定时扫描。

## 本版不做

自主注册、图片上传、自动照护提醒、站内通知、附加服务、在线支付、在线改期、自动换房、维护排班、详细审计查询、工作人员账号管理界面、多门店、视频及医疗功能。

用户明确暂不实现复杂异常处理：并发审核协调、请求幂等与重试、故障补偿、通知补发、逾期占房协调、入住检查失败后续处置、取消与入住竞争及结算故障注入暂不作为MVP交付与验收条件。后续课程分析可描述为扩展问题，不写成已实现功能。

这不移除登录权限、资源归属、必填与日期检查、正常分房时的可用性检查、状态前置条件和金额计算。首版对不满足前置条件的操作给出简单提示，不建设专门异常工作流。

## 计费示例

日价80元，预约11月1日至4日，计划3天，基础费240元。11月2日才入住或11月3日提前接回，基础费仍240元；11月5日离店为320元。金额以人民币分保存，门店日期按Asia/Shanghai计算。
