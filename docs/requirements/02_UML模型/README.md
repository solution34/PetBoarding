## 1. Visio 模板与图形

在 Visio 中执行：**文件 → 新建 → 搜索“UML 用例”或“UML Use Case” → 选择空白模板 → 创建**，使用随模板打开的 UML 用例模具。模板入口和关系类型参考 [Microsoft：创建 UML 用例图](https://support.microsoft.com/zh-cn/visio/create-a-uml-use-case-diagram)。不同版本中文名称可能显示为“执行组件”“包括”“归纳”，以图形和语义对应。

| 图中元素 | Visio 模具形状 | 绘制要求 |
|---|---|---|
| 五类人员角色 | 参与者 / Actor / 执行组件 | 小人，名称在下方 |
| 外部支付平台 | 参与者的矩形表示，标注 `«actor»` | 不画成系统内部功能 |
| 系统功能 | 用例 / Use Case | 淡黄色小椭圆，宋体名称移至椭圆下方 |
| 人员或平台参与功能 | 关联 / Association | 细粉红实线；按教师样式设置普通箭头，指向用例 |
| 必需的公共行为 | 包含 / Include | `«include»` 虚线箭头，基础用例指向被包含用例 |
| 条件性附加行为 | 扩展 / Extend | `«extend»` 虚线箭头，扩展用例指向基础用例 |
| 同一目标的特定办理方式 | 泛化 / Generalization | 实线、空心三角，具体用例指向一般用例 |
| 系统名称 | 注释 / Note | 折角注释 |

沿用教师的白底、淡黄色小椭圆、粉红色细线、椭圆下方名称和折角注释；不增加大标题、可见用例编号或底部图例。每个角色放在本分区左边，用例放在右边，同一区内再展开包含、扩展或泛化。所有关系使用端点到端点的带箭头直线，不设置折点、不共用折线干路；关联为实线普通箭头，包含与扩展为虚线普通箭头，泛化为实线空心三角箭头。

后续类图使用 Visio 的 UML 类模板，顺序图使用 UML 序列/顺序模板，活动图使用 UML 活动模板，不改用其他软件图源充当 Visio 工程。

## 2. 六个分区

| 位置 | 参与者 | 直接关联的用例 |
|---|---|---|
| 左上 | 宠物主人 | 维护宠物资料、查询可预约房源、提交寄宿预约、支付预约全款、查看订单及进度、查看照护情况、核对与离店 |
| 右上 | 前台接待员 | 维护可预约房源、线下正式接单、安排照护责任、办理入住、核对与离店、查看订单及进度、上报突发事项 |
| 左中 | 宠物照护员 | 查看订单及进度、安排照护事项、登记照护结果、上报突发事项 |
| 右中 | 店长 | 查看订单及进度、查看照护情况、安排照护事项、处理突发事项；需要时进入紧急调整扩展 |
| 左下 | 系统管理员 | 管理账号与权限 |
| 右下 | 外部支付平台 | 支付预约全款 |

每个分区独立连线，不再让多角色汇聚到整张图中央的一个共享椭圆。相同名称且编号相同的椭圆是同一用例的不同视图，不增加功能或数据权限。例如 UC-03 在主人、前台、照护员、店长区分别显示，但仍分别限制为本人订单、接待所需订单、分配订单和全部门店订单。

支付平台区重复显示 UC-14，含义是平台协作处理该用例。店长区 E-01 由 UC-11 条件扩展触达，无须再单独从店长拉一条长线。

## 3. 用例关系

| 来源 | 关系 | 目标 | 依据 |
|---|---|---|---|
| UC-02 提交寄宿预约 | 包含 | S-01 校验并预留房间 | 提交时必须重新验证并预留实际房间 |
| UC-17 线下正式接单 | 包含 | S-02 核验预约及付款 | 实际接收前必须核对成功预约及全款结果 |
| UC-12 核对与离店 | 包含 | S-03 核验接回人信息 | 交还宠物前必须核验接回人；在前台区展开 |
| E-01 紧急调整照护人员 | 扩展 | UC-11 处理突发事项 | 需要更换或增派照护人员时，在“人员调配”扩展点执行 |
| UC-05A 初次分配照护员 | 泛化 | UC-05 安排照护责任 | 接单后首次确定责任人的具体方式 |
| UC-05B 日常转派照护员 | 泛化 | UC-05 安排照护责任 | 更换责任人并留存交接的具体方式 |

UC-05A、UC-05B 细化已经确认的 FR-05 / UC-05 两种路径，不新增功能需求编号。二者都实现“使本次寄宿具有明确的当前照护责任人，并保留操作记录”的目标；初次分配要求尚未分配，日常转派要求已有责任人且需要交接。

紧急调整保持为店长处置异常时的条件扩展，不让它继承前台关联的一般用例，以免引入前台可执行紧急调配的歧义。店长不继承前台或照护员角色，管理员也不继承业务人员权限。

不为了压缩数量添加“管理一切”之类空泛父用例，也不把查询、预约、付款、接单、入住的先后关系画成泛化、包含或扩展。登录继续作为受保护操作的前置条件。

## 4. 当前文件与绘图步骤

| 文件 | 用途 |
|---|---|
| [实验二 Visio 图源](2024051604119冯春霖.vsdx) | 微软 UML 用例模板底稿，7页原生矢量图元及连接引用；Visio 实际打开检查待补 |
| [PNG 分区布局参考](01_宠物寄宿系统_用例图.png) | 3920 × 3600 像素；供在 Visio 中照图排版，非 Visio 导出 |
| [SVG 分区布局参考](01_宠物寄宿系统_用例图.svg) | 可缩放预览，非 Visio 原生图源 |
| [布局与用例编号数据](01_Visio用例图布局.json) | 保存位置、标识、关系方向和重复视图映射；不是 Visio 模板 |

1. 在 Visio 中使用第 1 节指定的 UML 用例模板和模具，新建正式绘图。
2. 根据第 2 节按六个区域排放参与者，再摆放各自用例；相同用例的重复视图沿用同一编号。
3. 使用关联连接器连接角色和本区域用例，粘附端点；连接形式选择直线，去掉中间折点，设置末端普通箭头。
4. 使用包含、扩展、泛化连接器添加第 3 节的六条关系，也采用直线连接；包含与扩展保留虚线和关系标注，泛化保留实线空心三角，确认方向。
5. 调整颜色、字体和文字位置；必要时用 Visio 文本块工具把名称移至椭圆下方。
6. 保存原生 `.vsdx`，重新打开检查元素可编辑及端点粘附，再从 Visio 导出提交图片。需要复用时另存 `.vstx`；未实际保存前不称模板已创建。
