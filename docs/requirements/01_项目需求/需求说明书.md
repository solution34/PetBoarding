# 宠物寄宿 Web 系统需求说明书

版本：V2.0 需求草案；整理日期：2026-11-14。

状态：根据本轮项目讨论整理，核心业务流程已确认，具体政策仍待明确。本文件是新需求的统一阅读入口。现有代码、API 契约和历史验收记录仍对应 V1.2，不代表已经实现本草案。旧 UML 模型及对应报告草稿已删除，待依据本轮需求重新建立。

## 1. 项目描述与目标

本项目拟开发一个宠物寄宿 Web 系统。宠物主人在线维护宠物资料、提交订单、查看订单进度及照护记录；店长审核订单、安排寄宿资源、分配负责店员并协调异常处理；店员办理入住交接、执行照护、登记结果及上报异常；系统管理员负责账号及角色权限管理。

系统以寄宿订单为主线，记录预约、接单、入住、照护、异常处理、结算及离店过程，使主人能够远程了解寄宿情况，店长能够统筹门店业务，每只寄宿宠物有明确的负责店员，照护和异常处理过程可查询、可追踪。

需求来源为用户在本轮会话中的业务说明与确认，并非真实门店访谈。课程要求见[课程与提交说明](../03_实验报告/课程与提交说明.md)。

## 2. 范围与角色

| 角色 | 主要职责 | 权限边界 |
|---|---|---|
| 宠物主人 | 维护宠物资料、提交和查看订单、查看照护记录、核对费用并接回宠物 | 仅访问本人及本人宠物的相关信息 |
| 店员 | 查看负责的订单，办理入住交接，安排或执行照护事项，登记结果、上报异常及办理宠物交接 | 按分配职责办理业务；跨员工代办权限待明确 |
| 店长 | 审核订单、安排寄宿资源、分配店员、查看门店订单及照护情况、协调异常、处理结算与订单结束 | 统筹门店寄宿业务 |
| 系统管理员 | 管理账号及角色权限 | 不因管理员身份自动取得门店业务操作权限 |

宠物是业务对象，不是使用系统的参与者。远程查看指订单及已登记的照护信息。视频监控、在线诊疗、站内聊天、自动提醒、图片上传和多门店统筹尚未确认为本轮必需功能。

店长联系主人是已确认的业务活动；电话、线下联系或系统消息等具体渠道待明确。主人账号的注册或开通方式同样待明确。

## 3. 完整业务流程

| 步骤 | 操作角色与活动 | 系统记录或结果 |
|---|---|---|
| 1. 业务准备 | 管理员管理门店人员账号及权限；店长掌握寄宿资源和人员安排 | 可用账号、权限及业务基础资料；资源管理方式待明确 |
| 2. 宠物建档 | 主人填写宠物基本信息、联系方式、饮食习惯和特殊照护要求 | 形成可用于下单及照护的宠物资料 |
| 3. 在线下单 | 主人选择宠物，填写计划入住和离店时间及寄宿需求 | 生成可查询的待确认订单；费用展示规则待明确 |
| 4. 订单审核 | 店长核查寄宿资源、人员安排及特殊要求，接受或拒绝订单 | 接受后进入待入住；拒绝时保存原因 |
| 5. 分配照护责任 | 店长指定负责店员，店员查看订单和照护要求 | 保存责任人，供主人、店长和负责店员查看 |
| 6. 实际入住 | 店员核对宠物、订单、身体状况、照护要求和交接物品 | 登记实际入住及交接情况，订单进入寄宿中；不符情况交店长协调 |
| 7. 日常照护 | 店长或负责店员安排照护事项，店员执行并登记 | 保存计划与实际执行情况，主人和店长可查看 |
| 8. 异常处理 | 店员登记并上报，店长联系主人并协调处理 | 保存上报、联系、处理过程和结果 |
| 9. 结算离店 | 店长与主人核对费用；按最终确定的付款与交接规则登记收款，由店员核对接回人并交接，店长在满足条件后结束订单 | 保存实际离店及结算信息，释放资源、结束本次照护责任并保留记录 |

取消、改期、续住、未按时到店、提前或逾期接回需要细化。付款时点、支付渠道以及欠款时是否允许离店均未确定，见第 8 节。

## 4. 功能需求与用例清单

FR-xx、UC-xx、AC-xx 为本草案编号，不与 V1.2 的 FRxx、UCxx、TCxx 自动等同。本表作为功能和用例的初步追踪表，详细场景及用例关系在建模阶段进一步核验。

| 需求 | 用例 | 系统应提供的能力 | 主要角色 |
|---|---|---|---|
| FR-01 | UC-01 维护宠物资料 | 维护主人名下宠物的基本信息、饮食习惯、健康情况和特殊照护要求 | 主人 |
| FR-02 | UC-02 提交寄宿订单 | 接收宠物、计划时间和寄宿需求，校验后生成待确认订单 | 主人 |
| FR-03 | UC-03 查看订单 | 主人查看本人订单及负责店员；店长查看门店订单；店员查看职责范围内的订单 | 主人、店长、店员 |
| FR-04 | UC-04 审核订单 | 提供订单、宠物资料及寄宿资源信息，支持接受或拒绝并保存结果与拒绝原因 | 店长 |
| FR-05 | UC-05 分配负责店员 | 为本次寄宿指定负责店员，保存分配结果并使相关人员可查 | 店长 |
| FR-06 | UC-06 办理入住 | 登记宠物核对、交接物品、实际入住时间及补充照护要求，完成后更新状态 | 店员 |
| FR-07 | UC-07 安排照护事项 | 安排事项，记录内容、计划时间和执行人员 | 店长、负责店员 |
| FR-08 | UC-08 登记照护结果 | 保存执行结果、实际执行人、执行时间及宠物情况 | 店员 |
| FR-09 | UC-09 查看照护情况 | 主人查看本人宠物的照护记录；店长查看门店照护情况及待完成事项 | 主人、店长 |
| FR-10 | UC-10 上报宠物异常 | 登记异常情况、发生时间和上报人，关联宠物及订单并供店长处理 | 店员 |
| FR-11 | UC-11 处理宠物异常 | 登记联系主人、协调处理的过程和最终结果 | 店长 |
| FR-12 | UC-12 结算与离店 | 支持费用核对、收款登记、宠物与物品交接及实际离店登记，满足结束条件后完成订单 | 主人、店长、店员 |
| FR-13 | UC-13 管理账号与权限 | 支持身份验证及角色访问控制，允许管理员管理账号和分配角色 | 管理员；身份验证涉及全部角色 |

寄宿资源维护需要支持接单判断，但按房间还是名额管理、谁维护价格尚待明确，不把旧版四种房型自动设为固定需求。

### 用例示例：UC-05 分配负责店员

- 参与者：店长。建议前置条件：订单已确认，存在可安排的店员。
- 输入：寄宿订单、选定店员。
- 主流程：店长查看订单和照护要求，选择负责店员并保存；系统登记分配结果，使负责店员可查看订单及要求。
- 成功结果：主人、店长和负责店员看到一致的责任人信息。
- 失败路径：店员账号不可用或操作者无权限时拒绝保存、说明原因并保留原结果。
- 待明确：最晚分配时点、店员是否确认接单、照护容量及转派规则。
- 关联：FR-05、BR-02、AC-05。

其他详细用例及模型对应关系待下一阶段补齐。登录可以作为受保护业务的前置条件，包含、扩展或泛化关系应有实际业务依据。

## 5. 业务规则与状态

| 编号 | 规则 | 确认状态 |
|---|---|---|
| BR-01 | 提交、确认、入住和完成分别记录；订单确认不等于实际入住 | 已确认流程 |
| BR-02 | 每只寄宿宠物有指定负责店员；建议责任关联本次寄宿订单 | 专人负责已确认，关联与交接细节待明确 |
| BR-03 | 事项创建与执行完成分开；完成记录保留实际执行人、时间和结果 | 已确认流程的记录要求 |
| BR-04 | 店员上报异常，店长联系主人并协调处理，保存结果；异常发生不自动结束订单 | 已确认流程 |
| BR-05 | 主人只查看本人信息，店员按职责办理业务，店长统筹门店，管理员管理身份和权限 | 已确认角色及权限推导，代办范围待明确 |
| BR-06 | 离店结束时保存交接与结算信息，释放资源、结束责任并保留记录 | 已确认流程，付款与离店先后条件待明确 |
| BR-07 | 接单前核查寄宿资源、人员安排及特殊要求，提交订单不自动表示接单成功 | 已确认流程，资源预留时点待明确 |
| BR-08 | 结束订单时处理尚未执行的照护事项并保留已执行记录 | 建议取消未执行事项，具体关闭规则待细化 |

主流程：`待确认 → 待入住 → 寄宿中 → 已完成`。

拒绝分支：`待确认 → 已拒绝`。取消的适用状态、申请及审批方式待明确。责任分配、照护事项、异常处理和付款分别记录其进展，不全部塞入订单状态。

## 6. 数据与质量要求

### 6.1 业务数据

以下是业务信息需求，尚非数据库表设计。

| 对象 | 需要记录的信息 |
|---|---|
| 用户与角色 | 账号、联系方式、角色、账号状态 |
| 宠物档案 | 所属主人、基本信息、饮食习惯、健康说明、特殊要求 |
| 寄宿订单 | 主人、宠物、计划时间、实际时间、寄宿安排及状态 |
| 寄宿资源 | 房间或名额、适用条件、使用安排；具体方式待明确 |
| 照护责任 | 订单与宠物、负责店员、分配时间及调整时的交接信息 |
| 照护事项与结果 | 内容、计划时间、执行人员、实际时间、结果及宠物情况 |
| 异常与处理 | 宠物与订单、描述、发生时间、上报人、联系情况、处理过程及结果 |
| 费用与结算 | 费用明细、应收金额、收款登记及状态；公式与渠道待明确 |

### 6.2 质量要求（由流程推导，待评审细化）

| 编号 | 要求 | 可检查条件 |
|---|---|---|
| NFR-01 | 权限控制 | 未登录用户无法执行业务；主人更换订单标识也不能读取他人数据；角色访问符合授权 |
| NFR-02 | 数据一致性 | 保存后不同角色看到一致的订单状态、责任人和照护结果；刷新后仍可读取 |
| NFR-03 | 操作可追踪 | 审核、分配、照护完成、异常处理及结算记录包含操作者和时间并关联业务 |
| NFR-04 | 明确反馈 | 成功、失败、缺少必填项和状态不允许操作时给出提示；失败不得显示为成功 |
| NFR-05 | Web 可用性 | 主人能在手机浏览器下单和查询，门店人员能在电脑浏览器完成业务；目标版本待明确 |

响应时间、并发规模、备份频率、保存期限及恢复目标待量化，不把未经确认的数值写成验收承诺。
