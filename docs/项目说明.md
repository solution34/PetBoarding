# PetBoarding 项目说明

PetBoarding 是《软件需求工程》课程的宠物寄养预约与照护管理项目。V1.2 提供单门店 Web MVP，主人和门店人员通过浏览器完成从预约到离店结算的流程，无需安装独立 App。

## 项目目标

统一记录宠物资料、预约安排、实际入住、照护任务和费用，支持课堂演示与需求验收。业务规则来自课程项目讨论，尚未经过真实门店访谈；当前成果用于课程与本地演示。

## 使用角色

| 角色 | 主要功能 |
|---|---|
| 宠物主人 | 维护本人宠物档案、查询房型与余量、提交和取消预约、查看照护及账单 |
| 工作人员 | 审核分房、驳回、入住登记、手动标记失约、安排并完成照护、登记线下收款和结单 |
| 管理员 | 维护四类房型价格和具体房间资料；不自动拥有工作人员权限 |

## 业务流程

1. 主人登录，选择或新建宠物档案。
2. 选择寄养日期，查询适合宠物的房型及连续可用房间数。
3. 确认价格后提交预约，保存日价快照；待审核不占房。
4. 工作人员审核并分配同房型的具体房间，预约转已确认。
5. 工作人员核对资料并办理入住。
6. 在住期间手动创建照护任务、登记文字完成记录，主人可以查看。
7. 离店时计算账单，主人核对，工作人员登记全额线下收款并结单，释放房间。

## 核心规则

- 房型为猫舍标间、猫舍豪华间、犬舍标间、犬舍豪华间；一张预约一只宠物，一宠一间。
- 价格在提交时锁定，审核不重新定价；提交前价格变化需主人再次确认。
- 日期区间为 `[开始日, 离店日)`，按 `Asia/Shanghai` 自然日计算，最少一天。
- 允许预约区间内延迟入住，需填写原因；提前接回或延迟入住均不减免原计划基础费。
- 基础费为锁定日价乘原计划天数；跨计划离店日增加自然日逾期费，不按小时收费。
- 结单后取消尚未完成的照护任务，历史记录继续保留。
- 主人只能访问本人宠物、预约、照护与账单。

## 技术与数据

| 部分 | 实现 |
|---|---|
| 前端 | Vue 3、TypeScript、Vite，位于 `apps/web` |
| 后端 | Node.js、TypeScript、Express，位于 `apps/server` |
| 数据库 | Node.js 内置 SQLite，默认文件 `data/petboarding.db` |
| 登录 | 服务端 Session、Cookie，预设演示账号 |
| 演示方式 | 构建后由 Express 同时提供网页与 `/api` 接口 |

业务规则、访问权限和最终金额由后端校验。数据库保存操作结果，刷新页面或重启服务不清空数据。数据库文件与构建产物不提交 Git，首次启动自动建表并初始化演示数据。

## 当前交付与边界

已提供网页 Demo、数据库初始化、API 文档、API 级验收脚本与操作指南。既有验收记录为30/30通过，具体执行条件与限制见[验收执行记录](验收执行记录.md)，不代表浏览器与移动端已完成全部走查。

自主注册、图片、自动提醒、站内通知、附加服务、在线支付、在线改期、多门店、视频和详细审计不进入本版；并发协调、幂等重试和故障恢复延期。

需求规格、用例与验收清单已更新到V1.2；UML、SVG、HTML阅读入口和实验报告仍待同步。课程的实验一教务系统体验分析独立完成，Demo不替代课程建模成果。
