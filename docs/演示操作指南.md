# V1.2 Demo 演示操作指南

本指南用于课堂演示与小组自查，按 V1.2 正常业务闭环组织。所有数据保存在本地 SQLite，刷新或重启服务后仍在。

## 1. 启动与重置

环境要求：Node.js ≥ 22.5（使用内置 `node:sqlite`），npm。

```bash
npm install          # 首次安装依赖
npm run build        # 构建后端 dist 与前端 apps/web/dist
npm start            # 启动演示服务，浏览器访问 http://localhost:3000
```

首次启动会自动创建 `data/petboarding.db` 并写入种子数据。需要恢复干净演示数据时：

```bash
npm run db:reset     # 删除本地数据库并重新建表、写入种子数据（需先 npm install）
```

演示账号（登录页有一键填入按钮）：

| 登录名 | 密码 | 角色 | 说明 |
|---|---|---|---|
| ownerA | owner123 | 宠物主人 | 王小明，有猫「咪咪」4.2kg、犬「旺财」18kg |
| ownerB | owner123 | 宠物主人 | 李小红，有犬「球球」30kg、猫「糖糖」3.8kg |
| staff | staff123 | 工作人员 | 张店长，负责审核、入住、照护、结算 |
| admin | admin123 | 管理员 | 赵管理，维护房型日价与房间资料 |

门店日期为 `Asia/Shanghai` 自然日；管理员账号不自动拥有工作人员业务权限（体现角色分离）。

## 2. 主线演示（约 5 分钟，真实日期）

以下操作可全部在同一个浏览器完成（用不同账号登录；也可用无痕窗口分别登录）。

### 2.1 主人提交预约（ownerA）

1. 登录 ownerA，进入「宠物档案」：可看到咪咪、旺财，可新增/编辑档案（名称、物种、体重、联系人必填，体重大于 0）。
2. 进入「查询与预约」：选择宠物「咪咪」，开始日期选今天，离店日期选 3 天后。
3. 系统展示匹配房型（猫舍标间 80 元/天、猫舍豪华间 120 元/天）、连续可用房间数与计划基础费。30kg 的球球只会匹配犬舍豪华间（体重上限过滤）；整段区间需同一间房连续可用，不拼接余量。
4. 选择「猫舍标间」→ 确认价格与“提前接回/延迟入住均不减费”说明 → 提交。订单变为「待审核」，此时**不占房**。
5. 若在提交前价格被管理员调整：页面会收到新价格与新总价，必须重新勾选确认后按新价提交（锁价时点=提交时服务端价格）。

### 2.2 工作人员审核分房（staff）

1. 登录 staff，进入「预约审核」：待审核列表显示宠物、体重、健康/疫苗备注、锁定日价。
2. 点击预约，加载候选房间（仅同房型、体重满足、整段区间可用且当前未被实际占用的房间）。
3. 选择具体房间「通过分房」→ 预约变为「已确认」，计划区间占房，价格快照不变。
4. 也可「驳回」：必须填写原因，预约转「已驳回」且不占房。

### 2.3 主人查看订单（ownerA）

「我的订单」→ 打开详情：状态、房型/房间、计划日期与天数、日价快照、照护记录与账单（未入住时无账单）。待审核/已确认可取消（填原因），无取消费。

### 2.4 工作人员办理入住与照护（staff）

1. 「入住办理」：已确认列表中选择订单；核对宠物、联系人、疫苗与健康说明；勾选检查通过、填写检查备注后登记入住。
2. 开始日当天入住无需迟到原因；若当前日期晚于开始日，必须填写迟到原因（不调整原离店日与基础费）。
3. 「在住照护」：为在住宠物创建照护任务（类型：喂食/饮水/清洁/其他；计划时间；说明），完成后填写文字记录。主人订单详情可实时看到任务与完成记录。
4. 到达计划离店日仍未入住，可「标记失约」（填原因）释放计划占用；本版无自动扫描。

### 2.5 离店结算（staff）

1. 「离店结算」：选择在住宠物，查看账单预览——基础费=锁定日价×原计划天数，逾期费=逾期自然日×锁定日价，提前接回不减免。
2. 主人核对账单后，工作人员勾选“主人已核对”，选择现金或线下转账，登记**全额**收款并结单。
3. 结单后预约转「已完成」、入住结束、剩余待完成照护任务转「已取消」并保留历史；未确认收款不能结单。
4. 切换回 ownerA 订单详情可查看最终账单与收款记录。

### 2.6 管理员维护（admin）

1. 「房型与房间」：修改房型日价（元→分保存）；之后新提交订单使用新价，历史订单快照不变。
2. 修改房间编号/最大体重；房间存在未完成预约（已确认/已入住）时只允许改名，修改体重会被拒绝并提示。

## 3. 可控日期演示（可选，展示延迟入住与逾期费）

正常演示使用真实日期。若需展示“延迟入住”“跨计划离店日逾期”，可用演示日期覆盖启动服务（仅演示/自动化使用，不是生产配置）：

```powershell
# 第 1 步：以 11-01 为“今天”启动，提交 11-01 至 11-04 的预约并审核分房
$env:PB_TODAY='2026-11-01'; npm start

# 第 2 步：关闭服务后，以 11-02 为“今天”重启，办理入住时系统要求填写迟到原因
$env:PB_TODAY='2026-11-02'; npm start

# 第 3 步：以 11-05 为“今天”重启，离店结算显示基础费 240 元 + 逾期 1 天 80 元 = 320 元
$env:PB_TODAY='2026-11-05'; npm start
```

`PB_TODAY` 同时影响业务记录时间戳的日期部分，账单中的实际入/离店日期与“今天”保持一致。`GET /api/health` 可查看当前生效的门店日期与覆盖状态。

## 5. 常见问题

| 现象 | 处理 |
|---|---|
| `npm start` 提示端口占用 | 设置其他端口：`$env:PORT='3001'; npm start` |
| 页面提示“前端尚未构建” | 先执行 `npm run build`（或 `npm run build:web`） |
| 数据想恢复初始状态 | `npm run db:reset` 后重新 `npm start` |
| 登录返回 401 / 会话失效 | 会话 8 小时过期，重新登录；退出后受保护页面要求登录 |
| 想查看接口是否存活 | 浏览器访问 `http://localhost:3000/api/health` |

## 6. 本版边界（演示时不要承诺已实现）

自主注册、图片上传、自动照护提醒、站内通知、附加服务、在线支付、在线改期、多门店、视频与详细审计不在本版；并发审核协调、幂等重试、故障补偿等复杂异常处理延期。演示只覆盖正常业务闭环及基本输入、权限、日期、状态与普通房态检查。
