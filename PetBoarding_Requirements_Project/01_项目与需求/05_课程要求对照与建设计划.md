# 课程要求对照与需求工程建设计划

日期：2026-10-23；适用项目：宠物寄养预约与照护管理系统 Web MVP。

本项目按用户提供的两份实验指导书及评分细则组织需求工程成果。课程报告是主要交付，网页 Demo 用于验证流程，不能替代建模与文字说明。本文件区分原文要求、项目落实方案与尚未完成的证据，不将计划记为已完成实验。

## 三 评分标准转为检查项

| 原评分标准 | 项目检查方式 |
|---|---|
| 未按时提交为0分 | 记录教师通知的真实截止时间，提前检查文件可打开与材料齐全；当前未提供截止时间 |
| 内容与题目完全相符 | 实验一使用教务系统题目；实验二至五统一使用宠物寄养选题，避免以网页截图替代UML |
| 图的内容没有错误 | 检查参与者边界、关系方向、多重性、消息时序、判断条件和状态结果，并跨图追踪 |
| 文字描述正确、详细 | 每张图说明建模依据、关键元素、主成功流程、异常分支及与需求的对应关系 |
| 格式美观 | 统一术语、字体、标题层级、编号和图题；最终报告逐页检查清晰度与分页 |
| 95分档有一两个亮点，100分档亮点突出且有创新 | 候选亮点为房间并发冲突控制、锁价及延迟入住的需求变更追踪；必须提供分析或实际验证证据 |

评分细则没有给出各项权重，也没有明确要求可运行Demo、微服务、指定技术栈或固定图数。不能自行编造权重，不能保证某个设计必然获得95或100分。项目保留四张顺序图属于覆盖业务的选择，不是指导书规定的最低数量。

## 四 项目需求与课程要求的边界

用户已明确采用网页形式及MVP目标，房型为猫舍标间、猫舍豪华间、犬舍标间、犬舍豪华间。当前MVP基线记录提交预约锁价、审核分房、区间内延迟入住、提前接回不减费等规则；这些是项目约定，不是指导书原文规定。

实现范围缩小不等于删去课程实验。照护自动提醒、图片、附加服务若不进入MVP，应在需求中标为后续版本，并同步从本版模型与报告主流程中移除或明确标识，不能继续混用旧版描述。

单体Web应用与关系型数据库是此前建议的实现方案，尚未确定具体框架。架构只需解释页面、业务服务和持久化职责及关键事务；不把技术选型作为课程已规定内容。

## 五 建设顺序及交付检查

1. 统一需求：将MVP基线合并到需求规格、用例和数据字典；增加房型对象，明确价格、入住、取消、失约、结算规则；区分已确认事项和待确认事项。
2. 完成实验二：形成参与者与用例清单、关系判断、完整用例说明，修订用例图。登录可作为前置条件；只有确有语义时才使用include、extend或泛化，不为展示符号虚构关系。
3. 完成实验三：修订领域类图并逐项解释属性、职责、多重性和生命周期；人工独立判断后与AI草稿对比。类图不等同于数据库ER图。
4. 完成实验四：先写具体场景步骤，再修订四张顺序图；将旧版审核锁价改为提交锁价，作为真实发生的需求变更分析，注明原图、变更依据和受影响消息。
5. 完成实验五：修订主业务活动图并走查各条路径；并行结构按业务需要使用，不能把具有事务依赖的收款和结单画成独立并行。
6. 更新需求追踪矩阵：需求编号 → 用例 → 类与关系 → 顺序/活动场景 → 验收场景；同步PlantUML、draw.io、SVG、HTML阅读入口与报告，避免同名图表达不同版本。
7. 形成报告：每份报告按目标、内容与依据、工具环境、真实实验步骤、图与详细说明、AI输出及人工修订、结果与反思组织。此结构是项目落实方案，并非教师提供的统一报告模板；收到模板后按模板调整。
8. 制作网页Demo：使用模型对应的数据与流程验证正常路径及冲突、越权、重复请求、提前/逾期离店；记录实测结果，未实施的压测与部署要求继续标为目标。
9. 提交检查：核对格式、源文件可编辑性、真实截图、成员信息、截止时间及教师接受的提交格式。

## 六 工具要求与证据管理

实验二正文明确写有使用Visio绘图。现有draw.io、PlantUML和SVG可以作为分析草稿，但不能称为Visio原生工程。严格按现有指导书执行时，应安排Visio绘制并保留源文件和实际操作截图；若采用替代工具，需有教师认可依据。不能通过修改后缀或把SVG导入后宣称完成可编辑UML模型。

每项证据保存实验编号、日期、执行人、需求版本、提示词、AI实际输出、人工发现的问题、实际修订及图版本。此前交互可以作为需求讨论证据，但不能虚构从未进行的人工独立绘图、Visio操作、访谈或软件测试。人员信息由本人填写。

## 七 尚需用户或教师提供的信息

- 实验一的教务系统具体功能、真实使用截图或功能列表，以及个人体验。
- 教师是否提供统一报告模板、截止时间、命名与分组要求。
- 课堂案例练习是否需随报告附交；Visio替代工具是否获准。
- MVP具体入住退房时刻、账号开通方式、站内通知范围，仍需在实现前确定。

这些信息不阻碍先修订宠物寄养项目的需求及模型；依赖真实体验或教师要求的部分保持待补充状态。
